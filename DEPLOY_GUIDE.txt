APEX FULL-STACK - DEPLOY GUIDE
==============================

OPTION A - RAILWAY + RAILWAY MYSQL (RECOMMENDED - ye aapka setup hai)
---------------------------------------------------------------------
  1) GitHub repo push karein (ye folder).
  2) railway.com -> New -> "Deploy from GitHub repo" -> APEX-FullStack.
     (Railway Dockerfile auto-detect karta hai - build command NAHI chahiye.)
  3) Railway MySQL plugin add karein: New -> Databases -> MySQL.
     DB ka naam "railwaydb" ya jo bhi ho - important NAHI hai.
  4) MySQL service select karein -> "Variables" (ya service page) ->
     "Generate" -> ab Railway khud aapke WEB service mein ye env var
     inject kar dega:
         DATABASE_URL = mysql://user:pass@host:port/railwaydb
     (Private SQL URL ka matlab - link button se DB ko web service se
      LINK karein; link karte hi DATABASE_URL web service par auto aata hai.)
  5) Web service -> Variables mein ye bhi add karein:
         APEX_ADMIN_USER = admin
         APEX_ADMIN_PASS = (aapka strong password)
  6) Redeploy. Logs mein ye dhoondein:
         [APEX] Database engine: mysql
          APEX full-stack server ready
            Database: MySQL jdbc:mysql://...password=***
     Agar "engine: sqlite" likha aaye to matlab DATABASE_URL env var nahi
     mil raha - step 4 ka LINK dobara karein.
  7) MySQL dashboard "Data" tab mein sare tables honge:
     cars, bookings, booking_items, users, payments, documents, reviews,
     wallet, wallet_transactions, sessions, settings, drivers,
     owner_applications, notifications, chats, banned_cnic, owner_wallets.

  Important notes:
  - App MySQL env vars (MYSQL_URL / DATABASE_URL / MYSQL_*) dekhte hi
    SQLite use NAHI karta. Agar env vars set hon par connect na ho to
    app 30x 2-second baar baar retry karta hai (DB app se pehle ready
    ho sakta hai) - aur phir fail ho to CLEAR ERROR deta hai, kabhi
    silently SQLite par switch nahi hota (data-loss nahi hoga).
  - Uploads (CNIC, receipts, licence) ab DATABASE mein bhi store hote
    hain, is liye redeploy par bhi mehfooz rehte hain.
  - PORT env var Railway auto deta hai - app usi par listen karta hai.
    Aap PORT mat set karein.

OPTION B - RENDER (blueprint, SQLite)
-------------------------------------
  1) Render.com -> New + -> Blueprint -> repo select -> render.yaml.
  2) Deploy. Free plan par SQLite container ke andar hai (redeploy par
     reset hota hai). MySQL chahiye to Render par Postgres/MySQL service
     bana ke DATABASE_URL env var set karein - app khud switch kar lega.
  3) Deploy ke foran baad APEX_ADMIN_PASS badlein.

OPTION C - DOCKER (kisi bhi host par)
-------------------------------------
  docker build -t apex-fullstack .
  docker run -d -p 3030:3030 -v apex-data:/app/backend --name apex apex-fullstack
  MySQL ke sath:
  docker run -d -p 3030:3030 -e DATABASE_URL="mysql://u:p@host:3306/db" \
    -e APEX_ADMIN_PASS="..." --name apex apex-fullstack

OPTION D - VPS (Ubuntu/Debian) + systemd
----------------------------------------
  sudo apt update && sudo apt install -y openjdk-11-jdk unzip
  unzip APEX-FullStack.zip && cd APEX-FullStack/backend && ./build.sh
  /etc/systemd/system/apex.service:
     [Unit]
     Description=APEX full-stack
     After=network.target
     [Service]
     WorkingDirectory=/home/user/APEX-FullStack/backend
     Environment=PORT=8080
     Environment=APEX_ADMIN_USER=admin
     Environment=APEX_ADMIN_PASS=CHANGE_ME
     ExecStart=/usr/bin/java -Dapex.home=/home/user/APEX-FullStack/backend -cp out:lib/* com.apex.Main
     Restart=always
     [Install]
     WantedBy=multi-user.target
  sudo systemctl daemon-reload && sudo systemctl enable --now apex

TROUBLESHOOTING - "data is not saving" / "DB not connecting"
------------------------------------------------------------
  1) Log mein "Database engine:" line dekhein:
     - "engine: sqlite" + aap MySQL chahte hain  -> DATABASE_URL env var
       service par set/link nahi hai. Railway: DB ko service se LINK karein.
     - "engine: mysql" -> connected hai; aage ke steps dekhein.
  2) "MySQL not reachable yet (attempt x/30)" -> DB abhi ready nahi tha,
     app retry karta hai. 30 attempts ke baad fail = URL/credentials
     galat hain. Private URL copy karein (Public nahi), scheme mysql://
     ke sath (jdbc:mysql:// NAHI).
  3) Data purana nazar aaye ya har deploy par reset ho:
     - Pehle (isse pehle ke versions) MySQL env var missing hone par app
       silently SQLite par chala jata tha aur container disk wipe hoti
       thi = sab data khata tha. Ye ab fix hai (kabhi silent fallback
       nahi; clear error aata hai).
     - Ab data MySQL mein hai: Railway MySQL "Data" tab / "Query" tab se
       check karein.
  4) CNIC/receipt images deploy ke baad gayab: ab DB mein stored hain,
     naye uploads permanent hain. PEHLE se uploade ki purani images (jo
     sirf disk par thin) lost ho chuki hon to dobara upload karni paray.
  5) Auth error "Unable to load authentication plugin" ya SSL error:
     ab default useSSL=false + allowPublicKeyRetrieval=true hai (Railway
     compatible). Agar aapki hosting SSL force kare to env var
     MYSQL_SSL=true set karein.

CHECK AFTER DEPLOY
------------------
  https://your-host/api/health   -> {"ok":true,...,"engine":"mysql"}
  https://your-host/             -> customer site
  https://your-host/admin.html   -> admin login
  (engine "mysql" dekh kar pata chal jayega ke DB connected hai)
